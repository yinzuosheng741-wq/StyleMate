# RAG 优化方案

状态：设计方案，尚未实施本文件提出的新运行逻辑。依据：[2026-10-31 审计](../reports/RAG_AUDIT_20261031.md)。

后续已完成关键点复测，并提供可运行的开发诊断数据、逐项基线与验收条件，见 [关键点复核与实施清单](../reports/RAG_CRITICAL_REVIEW_20261031.md)。该复测尚未修改客户端运行逻辑。

## 目标与约束

优先解决“没有足够依据却给出具体建议”，再补齐常用知识，最后提升排序和回答效率。维持 Windows 便携、离线可用的基础能力、个人配置隔离和现有业务接口。

现状是 41 条已发布事实摘要、24 条待审核摘要、21 条项目规则。固定 28 条有答案题的真实混合 Recall@5 为 96.43%、MRR@5 为 0.9286；这些题主要围绕已发布知识，不能代表知识覆盖率或回答准确率。新诊断仍出现域外、未知材质及具体产品信息不足时的误召回。

本轮已经修复长文档证据丢失，6 个合成样本的切块与上下文标注短语覆盖均为 100%。因此暂时沿用 600 字符切块、80 字符重叠及 SQLite 向量后端；未来由真实文档与规模压测决定是否调整。

## 实施顺序

| 批次 | 交付内容 | 完成条件 |
| --- | --- | --- |
| 0：固定测量口径 | 语料快照、题集版本、开发/校准/保留测试划分，补测生产 Top K | 能在相同语料和参数下重放；旧结果不覆盖 |
| 1：问题约束与可回答性 | 原问题约束贯穿服务、图、工具和 Skill；证据支持状态统一 | 未知材质不套用已知材料护理，具体型号不借用通用尺寸作答 |
| 2：知识补齐 | 审核既有草稿，分材质与场景补充，发布新语料与索引版本 | 每条事实可定位来源且有适用条件；新知识有正例、边界及反例 |
| 3：检索对照实验 | 结构化过滤、混合召回、可选精排和摘录预算实验 | 相同语料与题集下，质量改善且延迟、资源成本符合预算 |
| 4：证据到回答 | 按子问题组织证据，输出结论与证据 ID，检查数字、操作及引用 | 直接结论有适用证据；不足、冲突与用户提供资料均明确说明 |
| 5：发布与维护 | 增量索引、来源变更复核、数据保护和版本回退 | 单批可回退；离线降级、个人数据完整性与 Windows CI 均通过 |

各批独立提交、验证和交付；一次只改变一类主要因素，避免同时扩库、更换模型、改切分后无法判断收益来源。

## 批次 0：先建立可信评测

保留历史兼容集和已用于优化的回归集。新建保留测试，覆盖常用材质、混纺、品牌/产品限制、未知材料、域外问题、否定、洗标缺失、多轮改口及跨页资料；至少同时包含直接支持、部分支持和无证据的问题。

生产 KnowledgeQuery 默认取 4 条，而既有主要表格报告 Recall@5，因此同时测 Recall@4、Recall@5、MRR、NDCG 和最终上下文证据覆盖。知识增长后，额外记录候选召回率与精排后证据保留率，定位是未召回还是被排序/裁剪丢失。

候选按“直接支持、仅提供背景、无关、与要求冲突”标注。直接证据之外的相关资料不自动算作完整答案，也不能把所有背景资料一概判错。引用 URL 合法性与逐句证据支持分开计量。

首批建议 120–160 个独立问题，覆盖约 40 个典型正例、30 个边界/缺条件问题、30 个难负例及 20 个多轮/长文档问题；数量是建设目标，不是统计充分性的保证。改写自同一问题或同一来源段落的样本归为一组，避免分散到不同集合造成泄漏。若仍全部由开发者标注，明确保留该限制；争议条目请未参与实现的人复核。

冻结保留测试后，只用开发与校准部分调整规则和阈值。保留测试一旦被分析用于调优，就转为回归资料，并另建下一版保留测试。

## 批次 1：原问题与支持状态先统一

在服务入口建立每轮独立的任务上下文，供确定性路径和模型图复用：

```text
原始问题 + 当前轮意图
衣物绑定及事实来源
材料/产品/处理方式/否定条件
缺失信息 + 当前允许的回答范围
```

原问题、owner/conversation 和衣物绑定由可信入口提供。模型可以改写检索词，但不能覆盖原问题约束；工具调用和结果验证始终按原约束复核。线程池与异步路径显式传播上下文，完成后清理，避免使用可串用户的全局可变状态。任务上下文不能授予写权限，原有身份和确认机制继续独立生效。

材料采用“已识别/未知”状态，保留原文和资料来源。字典未收录“醋酸”“腈纶”等名称时也应保留未知，不能因此进入不受材料限制的羊毛或 GORE-TEX 通道。用户填写的材料属于用户提供信息，不因为存进数据库就成为已核验事实。

可回答性分为：完整支持、部分支持、需补充条件、未找到证据、超出范围、证据冲突。各分支都返回一致的支持状态与缺失条件，而不是只依赖提示词：

- 缺洗标时先补问影响操作的条件；一般保养背景不能直接推导机洗、漂白或加热许可。
- 查询具体品牌/款号尺寸时，要求对应产品数据；模型删掉检索词中的“多少厘米”，也不能解除该要求。
- 混纺、涂层、衬里或装饰存在时，不能仅检出某一种纤维就给出整件衣物的处理许可。
- 无答案或域外问题可以说明限制；不能通过反复改写检索词，把任意返回片段变成有效依据。

此批验收同时覆盖公开聊天入口、选中衣物入口、care_guide 的短材质参数、模型改写参数和模型故障回退，避免只修复完整问句而遗漏工具内部路径。

## 批次 2：按覆盖矩阵补库

先核验并归并 24 条待审核记录；已由新摘要覆盖的草稿不重复发布。再依照[已有补充来源计划](../../data/knowledge/proposals/20261031-source-plan.json)小批补充真丝、亚麻和羽绒，随后补棉、羊绒、皮革及常见化纤。每次发布约 6–12 条有实质增量的摘要即可，数量服从证据质量。

每个材质/产品范围按“洗标判断、洗涤、干燥/熨烫、收纳、禁忌、适用条件”检查覆盖，并区分未覆盖与确认不适用。第二轮扩展混纺、鞋履、具体污渍与商务、面试、旅行等场景。婚礼等礼仪建议另注明文化背景、场合要求和适用范围，审美偏好继续作为建议或项目规则管理。

在现有来源和审核字段上逐步补充结构化属性：材料、衣物结构、处理动作、前置条件、适用产品、排除产品、事实/经验类型、知识版本和替代关系。缺字段表达未知，不把缺字段当成“适用于所有产品”。

采集流程：

```text
缺口清单 → 来源白名单 → 有限抓取
→ 去模板与定位章节 → 原创摘要及适用条件
→ 逐项核对 → 候选区 → 覆盖测试 → 版本发布
```

访问成功不是内容审核通过；403/超时不直接判失效，404/重定向优先复核。保留必要的定位、版本与内容哈希，遵循来源使用条件，公开仓库不默认收录网页全文。AI 核对标明为 AI 核对，不伪装成人工专家认证。

扩库将改变原来“无证据”问题的正确行为。因此先保留原语料快照；旧回归在旧语料上重放，新版本题集标注新语料的预期。所有改标均记录证据及原因，不能因检索失败而把正例改成负例。

## 批次 3：排序改进须通过对照

保留 BM25 离线基线与可选真实向量检索，按支持的材料、产品和动作条件在召回前过滤。对元数据未知的候选，区分“不能直接回答”和“完全不可检索”，避免过度过滤造成漏召回。

先做三组消融：BM25、BM25+向量+RRF、混合+可选重排。候选池先取约 12–20 条，最终上下文按生产 4 条起步；参数在校准集上确定。重排试验参考 [Sentence Transformers Retrieve & Re-Rank](https://www.sbert.net/examples/sentence_transformer/applications/retrieve_rerank/README.html)，但不因采用该流程就预设本项目一定提升。

优先比较便携部署的实际成本。重排服务为可选能力，故障时回退到既有混合/BM25，并记录降级；本地模型方案只有在包体、冷启动、内存和 CPU 延迟压测可接受后再考虑默认集成。不得为提高某个离线分数静默新增必需联网接口。

RRF 分数与向量相似度都不能直接当作答案置信度。拒答阈值和精排阈值分别校准，并报告保留测试上的误答与漏答；不把固定的 0.7/0.8 等数值直接用于所有模型。

## 批次 4：回答从证据组织出来

按子问题挑选直接证据，保留适用条件和排除条件；有多个动作或跨页问题时优先保证各子问题均有依据，再去重和裁剪。继续用有界上下文，初始按 4 条、同一文档最多两段执行；确有三段以上证据需要时，通过明确的多子问题预算扩展。

逐步改为结构化回答数据：结论/建议、支持它的证据 ID、前提条件、未覆盖部分。验证证据 ID 来自本轮可信检索、产品范围相容，具体数字和处理许可没有超出证据。部分可答时回答已支持部分，并明确剩余条件。

现有 URL 白名单保留为链接身份校验；另设逐句支持性检查。高风险处理建议在证据不足时优先回退到洗标/厂家说明或追问。自动评审模型适合作为离线筛查辅助，不能代替人工参考答案，也不默认给每次聊天增加一个评审模型调用。

## 验收、性能与维护

| 维度 | 验收口径 |
| --- | --- |
| 原问题约束 | 原材料、产品、否定与数字要求在所有路径中保留；契约回归全部通过 |
| 数据隔离 | 本轮增加用例中跨 owner/conversation 泄漏为 0，仍不宣称穷尽所有情况 |
| 检索 | 同语料的已标注原题不回退；补测生产 @4；扩库效果另报覆盖矩阵及新版本结果 |
| 可回答性 | 分别记录误把无依据判为可答、误拒绝有依据问题；在校准集定目标，在保留集验收 |
| 引用 | 分开报告链接合法率、结论有引用比例、引用实际支持结论比例，后两项需独立审读 |
| 时延与资源 | 分开记录索引构建、查询、重排、组装、模型首字与总时长的 P50/P95；报告包体、内存和索引体积 |
| 发布 | 原 527 项回归及新增检查通过；Windows CI、公开包启动和个人数据保护检查通过 |

新重排默认启用的前提是：相同题集的召回不退化、排序或人工相关性有稳定改善、误答不增加，且实测时延与部署成本在预算内。目标分数与成本预算应在试验前记录；本方案不承诺提高到某个未经测量的百分比。

用 100/1,000/5,000 条合成摘要及多文档分别压测，观察默认 SQLite 精确搜索的代价，再决定是否需要换索引。索引按内容哈希增量更新，版本与 Embedding 身份共同决定缓存；发布失败保留上一版可用索引。来源变更触发复核，不能自动覆盖已审核结论。

最先实施的是批次 0 与 1，随后用三类已核对来源做小批知识发布。只有这两部分稳定后，再判断精排的投入是否值得。
