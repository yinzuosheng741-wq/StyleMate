## 2. 本批修复

| 问题 | 处理 | 业务意义 |
| --- | --- | --- |
| “不要删除”“如果找到重复项，请删除”等也因关键词开放写入预览工具 | 引入保守的明确操作语法，区分否定、条件、问题、过去式与引用示例；保留单独明确操作子句 | 减少不必要预览，最终写入仍需确认 |
| 工具拒绝或预览准备失败后，确定性回复仍显示“已生成预览” | 先检查失败状态；写入只有实际返回 pending_action 才报告预览成功 | 界面不再误导用户确认不存在的操作 |
| 显式候选 ID 全失效后，过滤结果为空被当成无限制库存 | 返回无可用候选，不扩大到全部衣橱 | 用户选择的候选不会静默失效 |
| “今天不穿黑色”未进入既有确定性规则 | 聊天提取和规则端共享明确颜色排除语法，在组合前过滤 | 明确排除不能被偏好排序抵消 |
| “不穿黑色上衣”可能被粗略理解成排除所有黑色衣物 | 支持颜色与具体品类组合，以及多个颜色的明确列表 | 保留其他品类的可用单品 |
| 无解提示固定要求补齐上装、下装和鞋 | 展示工具返回的真实缺口或条件说明 | 不把约束无解一律说成品类缺失 |

路由仍是有限规则，不是完整自然语言语义理解。复杂、含糊表达应澄清，不能用此批固定测试的通过率宣称任意表达正确。

颜色语法目前覆盖代码中列出的常见中文颜色、排除词和品类；不代表已支持所有材质、状态、风格和否定嵌套。暂时条件不自动写为长期偏好。没有调整主架构，也没有引入额外 Agent。
