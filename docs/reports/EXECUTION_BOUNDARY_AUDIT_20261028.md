# 请求执行边界复查（2026-10-28）

## 实际问题与修复

现有工具中间件会检查截止时间，但图中的模型调用没有同样的前后检查。模型迟到时，服务仍可能将回答保存到会话；模型迟到并报错时，还可能启动确定性降级路由。

- 模型调用前后检查当前请求的共享截止时间；到期后不启动下一次模型调用，不接受迟到输出。
- 服务接住稳定的 `RequestExecutionDenied`，过期请求不再启动降级工具。
- 在生成会话回复前统一检查截止时间，覆盖预设、确定性业务路由及降级路径。到期只保存明确的停止消息和 `request_deadline_exceeded` 诊断，不保存迟到答案或引用；丢弃本轮临时捕获的穿搭卡片。
- 未绑定请求上下文的可信库调用保持兼容；每次公开 chat 的 ContextVar 都在结束后重置。已存在的待确认衣物操作仍由其独立的所有者、会话、快照及有效期校验控制。

## 检查范围与验证

本次复查入口服务、Skill 路由、模型与工具执行、结构化穿搭、记忆提取及遗忘、写操作确认，并运行完整既有测试（含前端 AppTest）。没有声称人工审阅所有源代码或用真实模型完成端到端验收。

新增 6 项时钟可控回归，验证迟到成功、迟到异常、调用前过期、穿搭工具后模型迟到、正常穿搭及确定性路由迟到。测试不用真实等待或付费模型。全量 337 项通过，Ruff 全量、编译、健康检查及演示来源审计通过；保留既有 DashScope 弃用提示。

## 边界与后续

这是同步调用返回后的结果验收和后续执行阻断，不是 SDK/线程的强制取消，也不保证整个 HTTP 请求在 90 秒时立刻返回。已开始的远端模型调用可能继续计费。若需要严格响应时间，应另行设计隔离任务、取消协议及迟到任务清理，不应仅用线程超时伪装成硬中断。

此次未修改语料、评测 gold、检索排名和前端样式；未证明召回率改善。下一步仍优先补齐可信材质知识和独立用户任务标注，再用真实 embedding 与业务任务成功率评估收益。
