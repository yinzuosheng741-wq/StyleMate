# RAG 关键点复核与实施清单

日期：2026-10-31。范围：当前本地代码、当前已发布知识和离线执行路径。本轮新增诊断程序、测试数据和方案，没有修改客户端运行逻辑、调用个人 API 或扩充已发布知识。

## 判断

当前最需要优化的是“检索到了什么资料，这些资料是否有资格支持当前问题”。先固定问题约束和可回答性，再补知识。现有数据暂不支持优先更换切块算法、向量数据库或默认引入重排模型。

本轮 [23 个自动契约用例](../../evaluation/rag_critical_cases.json)中 14 个符合预期、9 个触发问题。用例专门覆盖已发现的薄弱点，并包含正向控制，不代表线上问题分布、独立测试集准确率或真实模型任务完成率。脚本模型只注入指定工具参数；没有评估真实模型是否会产生这些参数。

基线：[完整机器可读结果](../../artifacts/reports/rag/rag-critical-review-20261031.json)。记录了代码指纹、语料与题集 SHA-256、逐题结果及测量范围。知识变更后不得继续把旧语料上的“无证据”标签直接套用到新语料。

这里的“全过”是有限契约回归的合并条件，不是对真实世界 100% 正确的承诺。背景证据并非一律无用；当前 schema 无法明确区分其用途，因此本轮自动契约采取保守口径：不能以普通 evidence_found 暴露为直接答案依据。引入部分支持状态后，须升级契约并检查每个动作的支持范围，保留旧版结果。

## 分批改进项

### 批次一：可信约束与材料边界

1. 新建不可变的任务约束数据，包含原问题、当前轮衣物引用及信息来源、材料/品牌/款号、请求动作与否定项。身份和写入授权继续由现有权限机制校验。
2. 在 `AgentService` 创建并传入 `ToolContext`/工具闭包；模型工具 schema 不开放覆盖这些字段。图、确定性路径、选中衣物及故障回退复用同一约束。
3. 检索词与任务约束分开。工具若改成另一种材质或删除具体产品要求，返回可解释的缺失/冲突信息，不将改写后的问题视为用户新授权。
4. 未知材料保留原文；未知不等于任何材料均可。用户材料声明、图片识别和厂家洗标注明信息来源；标签缺失时不授权依赖标签的处理动作。
5. 先跑本轮 23 题，再加并发跨用户/会话、超时后的上下文清理、多轮改口测试，确保约束传播没有引入串线。对材质边界的改动不能破坏已知材料正例。

### 批次二：支持状态与回答组装

1. 工具结果增加统一的支持状态、缺失条件、可回答子问题及证据 ID。execution success 不等于业务可答。
2. 混纺、装饰、涂层、具体产品尺寸和洗涤/漂白/加热等动作需要各自适用证据。来源 URL 合法、材料有交集、文档属于用户都不足以证明具体结论。
3. `KnowledgeQASkill._valid_cited_hits` 对用户文档保留检索权限，但不因 document_id 而免做支持性判断；针对“上传了通用量衣指南但没有该款数据”补反例。
4. 展示层分别渲染“能够回答的部分”和“还需要的信息”。确定性回答也要遵守支持范围，不能展示一段已注明不适用于未知材料的操作后，只追加通用免责声明。
5. 用 8 个审读挑战逐项记录结论、证据原文位置、遗漏条件、是否出现未经支持的数字/操作。自动评审只能作辅助；未经独立审读，不报引用实际支持率。

### 批次三：有界扩库与检索实验

1. 沿用 [既有来源计划](../../data/knowledge/proposals/20261031-source-plan.json)，先审核、去重和小批发布，再扩展到混纺、污渍和场景。每条摘要必须带适用/排除范围。
2. 每个事实单元至少配 3 类题：直接支持、范围相近但不适用、缺少关键条件。同源段落和改写题保持同组，防止拆分泄漏。
3. 构建新的开发、阈值校准、独立保留数据；本轮所有可见题只作开发回归。先预登记错误类型、目标和资源预算，再看保留结果。
4. 在真实证据无法进入前 4 条时，再比较候选池、结构化过滤、去重和精排。不能向端到端评测候选中注入正确答案；保留离线 BM25 降级能力。

新数据阶段分别记录：约束丢失数、不适用证据暴露数、错误拒答数、支持状态混淆矩阵、Recall/MRR/NDCG@4、候选到上下文证据保留率、逐结论支持性、各阶段 P50/P95。不要把这些维度合并成一个“RAG 准确率”。

## 重放与完成条件

```powershell
.venv/Scripts/python.exe -m evaluation.rag_critical --output artifacts/rag-critical-next.json
.venv/Scripts/python.exe -m evaluation.rag_critical --output artifacts/rag-critical-strict-next.json --require-pass
.venv/Scripts/python.exe -m pytest tests/evaluation/test_rag_critical.py tests/rag/test_rag_audit.py tests/skills/test_care_scope.py -q --basetemp .pytest-tmp-critical-next
```

普通模式保留所有问题并返回报告，命令成功不表示契约全部通过。严格模式在任一自动契约不通过时返回非零退出码；目前预期会失败，不能提前当成已达标的发布门禁。两种模式都拒绝覆盖既有结果。

下一批的完成条件：有限契约全部满足或通过可审查的新版部分支持契约；已标注历史正例无退化；新的正例、反例、用户隔离与回退检查通过；全项目验证通过后，再构建和检查 Windows 公开便携包。语义支持性需单独审读，不以普通单元测试通过代替。

本轮工程验证：相关检查 34 项通过；全项目 535 项测试通过，依赖、约束、健康检查、素材、Ruff、编译和原固定评测门槛均通过，验证期间源码指纹未变。新增评测器测试检查的是诊断是否如实识别并报告失败，不能据此将上述 9 个业务契约问题宣称为已修复。验证记录保存在本地 `artifacts/rag-critical-validation-20261031/validation.json`。
