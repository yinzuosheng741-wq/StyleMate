# 常用指标实测记录

日期：2026-10-31。被测业务版本：`d4d9f6c`。本次只新增评测代码、题目和报告，没有修改业务实现。原有 60 条 RAG 历史基线保留，未覆盖或更改原质量门槛。

## 样本与条件

- 独立业务场景 30 条，每条重复 3 次，共 90 次本地任务。未配置对话模型，使用真实应用服务、真实工具、内存衣橱及固定 22℃ 天气；前置建库和多轮准备消息不计入任务耗时。
- 从中选择 10 条工具编排任务，每条重复 2 次，共 20 次真实模型图执行。使用已配置模型，temperature=0.2、max_tokens=600；衣橱为合成数据，天气为模拟数据。模型经过真实网络，工具执行使用当前项目代码。
- 新检索题集包含 20 条有答案问题和 4 条无答案问题，覆盖现有已审核知识；分别测量 BM25、离线 Hash 向量、真实 Embedding 向量与混合检索。单模式每题执行一次，未加入人工重排。
- 真实文本、视觉、向量、天气连接探针各 3 次。视觉仅发送生成色块，天气使用公开示例城市杭州，未启用 IP 定位。
- SQLite 数据验证执行 50 组增删改查、重新打开数据库和用户隔离，共 200 项状态检查；使用临时数据库。

这些是项目作者编写的小规模场景，不是外部用户盲测；同题重复不等同于独立用户样本。报告中 Wilson 区间只作描述，小样本 P95/P99 不代表长期分布。

“功能验收”要求预期工具被调用，并满足该题明示的文本、来源、库存组合、选中单品、待确认状态和无意外写入等条件；允许额外只读工具。“工具集合完全一致”另行统计。原始报告的严格口径会把额外工具算失败，因此严格通过率为本地 78/90、真实模型 13/20；分析版同时保留两种口径，原始执行数据未改动。

工具执行状态成功不等于任务成功；本地工具失败中包含故意注入的天气异常。耗时统计包含成功与失败任务。图执行的完整耗时包括模型往返及工具执行，但不包含界面绘制、初始化和前置会话准备。

验收规则不是完整语义评分：人工抽查发现一条单品信息回答没有复述衣物名称，但回答了所问类别和未知材质，被有限文本断言判失败。保留该失败，不据此上调自动通过率。实际回复是否完整、合理及逐条得到证据支持，仍需人工评分。

## RAG 消融

以下质量指标仅在 20 条有答案题上统计；拒答率在另外 4 条无答案题上统计。Precision@5 按已标注记录 ID 计算，可能漏标其他相关条目，且每题通常只有 1–2 条标注证据。

| 策略 | Recall@5 | Precision@5 | Hit@1 | MRR@5 | nDCG@5 | 检索 P50 / P95 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| BM25 | 95.00% | 22.00% | 90.00% | 0.9250 | 0.9235 | 3.37 / 6.02 ms |
| 离线 Hash 混合 | 92.50% | 21.00% | 90.00% | 0.9250 | 0.9082 | 6.47 / 8.76 ms |
| 真实向量 | 95.00% | 22.00% | 85.00% | 0.8917 | 0.9004 | 532.83 / 860.34 ms |
| 真实混合 | 95.00% | 22.00% | 95.00% | 0.9500 | 0.9500 | 476.08 / 1017.46 ms |

同题集的真实混合检索相对 BM25：Hit@1 提高 **5 个百分点**，MRR@5 提高 **0.025**；Recall@5 相同。它是策略消融，不是软件版本升级效果。真实向量与混合均无记录到的向量调用失败；其耗时包含查询 Embedding API，索引构建另计，不与离线毫秒数混称为模型回复时间。

所有模式的无答案拒答率均为 **2/4，50%**。两个明显无关问题仍召回了衣物资料，说明当前没有足够有效的域外拒答机制。

原有历史 60 题的 Recall@5 仍为 **22.50%**；新题集聚焦已发布知识、题目与覆盖条件不同，不能写成“召回率由 22.5% 提升到 95%”。

## API 探针与输出预算对照

| 接口 | 探针通过次数 | 平均耗时 |
| --- | ---: | ---: |
| 文本（当前 64-token 连接探针） | 1/3 | 2.27 s |
| 视觉（生成色块） | 3/3 | 0.74 s |
| Embedding（短文本） | 3/3 | 0.51 s |
| 天气（示例城市） | 3/3 | 0.29 s |

上述是单轮探针通过率，不能称为服务长期可用率，也不表示视觉识别准确率。文本探针原始失败没有保留分类，未武断认定为网络故障。

追加同提示输出预算对照，各 3 次：64 token 下有最终内容 **2/3**，600 token 下 **3/3**。全部 HTTP 200；失败样本存在 reasoning_content，finish_reason=length，最终 content 为空。说明当前模型的思考消耗可能让小预算探针误报失败。该对照保留原始结果，是探针参数观察，不是应用任务成功率提升。尚未修改生产探针参数。

真实模型图执行的提供方累计返回用量：输入 **105,738 tokens**、输出 **9,481 tokens**，合计 **115,219 tokens**；不包括其他 API 探针和 Embedding。未按价格估算费用，未进行流式请求，TTFT 未测量。高并发吞吐、长期稳定性、专家评定的忠实度与正确率也未在本轮测量。

## 数据与异常边界

SQLite 状态检查 **200/200** 通过，覆盖正常 CRUD、重新连接后的持久化与用户隔离。没有测试断电恢复、磁盘损坏或多进程同时写入，不能称为所有条件下的数据一致性 100%。

业务场景中的天气异常和模型异常均有降级结果。否定删除请求虽然没有实际写入或生成确认操作，但确定性路径仍尝试了被权限层拒绝的删除工具，因此被评为任务失败：安全防线生效，交互路由仍需改善。

未知材质洗护在真实模型编排中两次都继续检索了羊毛资料，未满足保守的来源边界要求。这是后续需要强化的工具前置约束，不能被“工具调用成功率 100%”掩盖。
