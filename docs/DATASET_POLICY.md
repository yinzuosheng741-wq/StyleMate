# 离线题集维护规则

## 三层题集

1. **历史兼容集**：`agent_cases.json`、`graph_cases.json`、`rag_cases.json`。保留原有 101 条评测与历史报告，继续执行固定质量门槛。60 条检索题包含未发布知识和旧范围标签，不能单独当作当前系统的完整质量指标。
2. **固定回归集**：`benchmark_cases.json`，30 条业务场景及 24 条检索问题。保留本次优化前后比较所用的原题和原标签。新增工具导致合理的额外只读调用时，工具集合一致率和功能验收通过率分开报告。
3. **扩展验证集**：`benchmark_validation_cases.json`，继承固定回归集，并新增 20 条业务场景与 16 条检索问题。合并后为 50 个业务场景、40 条检索问题；其中检索含 28 条有答案、12 条无答案问题。合并时分别标记 regression 和 validation，分别报告业务结果。

新增验证题在实现优化规则之后、首次执行验证之前编写。它们仍由项目开发者编写和标注，不是外部独立盲测；一旦用于分析或调参，就应视为后续的回归资料，不再称为未知测试题。

## 标注与版本

- 有答案问题需标注具体证据记录 ID；新题集加载时检查 ID 是否为当前已发布、已审核记录。仅字段齐全不等于内容真实，仍需按知识审核契约核对来源。
- 无答案问题保留空相关 ID，覆盖明确域外问题、未覆盖面料和不存在的知识。不能把检索失败自动改标为无答案，也不能用新的拒答规则反向生成全部负例。
- 针对含糊材质、缺少目的地或天数、指代不明的任务，标注应追问的条件，不奖励猜测答案。
- 多轮题保留完整前置消息；测试会话重置与跨用户隔离；人工复核同名衣物和选中衣物的标签。
- 版本改变时追加新文件；`extends` 只允许加载同目录父题集。禁止重复 ID、空问题和引用未发布记录。父题集的回归问题原样继承。
- 在保持版本、语料、模型和验收口径一致时才做前后比较；题集变更的总体分数只作为新版本结果。

## 本轮暴露的覆盖问题

原历史 60 条检索题中，只有 17 条的目标记录全部已发布，2 条部分发布，41 条目标未覆盖；17 条中又有 4 条存在有限范围冲突。历史 Recall@5 保留为 22.5%，同时报告标签覆盖，不通过删题抬高该数字。

原新基准的 20 条有答案问题主要围绕已发布知识，不能代表所有洗护与穿搭需求，因此在 v2 增加跨轮、口语、否定、指代、未覆盖知识和域外问题。v2 首次验证仍发现“给我配身上班的衣服吧”未命中本地搭配路由，以及税务问题的误召回；本轮保留失败，未对验证结果继续调规则。

## 运行

```powershell
python -m evaluation.benchmark --output artifacts/new-regression.json
python -m evaluation.benchmark --cases evaluation/benchmark_validation_cases.json --output artifacts/new-expanded.json
```

真实模型与 Embedding 评测需显式添加 `--online --config-root "dist/personal/出行衣橱助手"`；使用合成任务和公开证据。输出包含题集、语料指纹与源码指纹，不覆盖已有文件。历史质量门槛继续由 `python -m evaluation.quality_gate` 执行。

本次结果确定后，50 条业务场景已接入离线回归测试：保留已知的 `v-outfit-colloquial` 未通过项，不要求它持续失败；其余场景若出现新的功能验收失败则阻止测试通过。该步骤明确把已经分析过的验证题转为后续回归资料，下一轮独立验证应另增题目。

后续应邀请未参与开发的人编写问题和复核相关证据，增加场景与难负例，并在调优前冻结评测规则。短期目标是降低已有任务的失败，而不是只扩大题量。
